### 発展(a)：Google ADKでの再実装

**実装上の違い**

Pydantic AI版では、`Agent(instructions=...)`でエージェントを定義し、`tool_plain()`でツールを登録する。一方、Google ADK版では、`Agent`の生成時にモデル・指示・ツールをまとめて指定し、`root_agent`として公開する。

今回は両者で同じシステムプロンプトとPython関数を使用した。Pydantic AI版は`run_sync()`を用いて実行する一方、ADK版では`adk run`コマンドを利用した。

**実験条件・結果**

| 項目 | Pydantic AI | Google ADK |
|---|---|---|
| 使用モデル | `gemini-3.5-flash-lite` | 同じ |
| システムプロンプト | `INSTRUCTIONS` | 同じ |
| 使用可能なツール | `search_glossary`、`get_lecture_summary` | 同じ |
| 入力した質問 | LoRAとQLoRAの違いは？ | 同じ |
| `search_glossary`の呼び出し | 2回 | 2回 |
| ツールに渡した引数 | `LoRA`、`QLoRA` | 同じ |
| `get_lecture_summary`の呼び出し | 0回 | 0回 |
| LLM呼び出し | 2回 | モデル応答イベント2件 |
| 関連する講義 | 第2回 | 第2回 |

Pydantic AI版では`--trace`、Google ADK版では`--jsonl`を使用してツール呼び出し履歴を確認した。

どちらもLoRAとQLoRAをそれぞれ検索し、検索結果に基づいて回答を生成した。回答内容は概ね一致し、LoRAは低ランク行列を用いて学習する手法、QLoRAはベースモデルの重みを量子化することでメモリ使用量をさらに削減する手法であると説明した。

**考察と限界**

今回の実験では、同じモデル・システムプロンプト・ツールを使用した場合、両フレームワークで同じツールが選択され、回答の要点も一致した。

一方、回答の表現には違いが見られた。ただし、各フレームワークでの実行は1回ずつであり、LLMの出力には変動がある。そのため、回答の違いがフレームワークに起因するとは断定できない。

また、検証した質問は1種類のみであるため、異なる質問に対するツール選択や回答の傾向については、追加の検証が必要である。
