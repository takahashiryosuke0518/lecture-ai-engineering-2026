  - モデルのリビジョン：`2fc06364715b967f1860aea9cf38778875588b17`
  - 乱数シード：`42`
  - エポック数：`20`
  - 学習率：`2e-4`
  - ウォームアップステップ数：`6`
  - LoRAランク：`16`
  - LoRA alpha：`32`
  - 最大系列長：`512`
  - 最大生成トークン数：`96`
  - 生成設定：`do_sample=False`

- **自分で学習を実行したか（`executed_training_myself`）**：
  - はい
  - 実行できた範囲：セクション0〜7（20エポック、40ステップの学習を完了）

- **学習前**：
  - `format_rate` = 0.0952（9.5%、2/21問）
  - `content_rate` = 0.0000（0%、0/21問）

- **学習後**：
  - `format_rate` = 1.0000（100%、21/21問）
  - `content_rate` = 0.9048（90.5%、19/21問）

- **退行した質問**：
  - なし（`regressed=[]`）

- **学習後に残った失敗と、その型**：

  1. 「成績はいつ出ますか」
     - FAQに成績発表時期の記載がないにもかかわらず、課題の提出期限を回答した。
     - `needs_review=false` と判定した。
     - 失敗の型：根拠なしの質問に断定した。

  2. 「オフィスアワーは事前予約が必要ですか」
     - FAQにはオフィスアワーの開催日時しか記載されていないが、その日時を回答した。
     - `needs_review=false` と判定した。
     - 失敗の型：根拠なしの質問に断定した。

  - 学習後に形式の崩れは確認されなかった。

- **知識を問う質問（セクション6）の結果（学習前の分類 → 学習後の分類）と気づいたこと**：

| 質問 | 学習前 | 学習後 |
|---|---|---|
| この講座の最終課題の締切はいつですか | format_error | asserted |
| 担当教員の名前は何ですか | format_error | needs_review |
| 次回の講義のテーマは何ですか | format_error | needs_review |
| 課題の提出期限はいつですか | format_error | asserted |

  - 学習前は4問とも指定されたJSON形式を満たさなかった。
  - 学習後は2問が`needs_review`、2問が`asserted`に分類された。
  - 最終課題の締切はFAQに明記されていなかったが、モデルは通常の課題の提出期限を回答した。
  - 担当教員と次回の講義テーマについては、FAQに記載がないため確認を求めた。
  - FAQに記載されている課題の提出期限については、正しく回答した。

- **学習で変わったこと・変わらなかったこと**：

  学習前もプロンプトでJSON形式を指示していたが、形式遵守率は9.5%だった。LoRAによる学習後は100%となり、設計者が指定した出力形式を守れるようになった。

  また、内容正解率も0%から90.5%に改善した。ただし、今回の内容評価では`needs_review`の一致が必要であるため、学習前に回答内容がおおむね正しくても、キーが欠けていれば不正解となる。このため、内容正解率の改善には、回答形式が整った影響も含まれている。

  一方、FAQに根拠がない質問への誤回答は学習後も残った。特に、「課題」と「最終課題」のように意味が関連する表現に対して、FAQの情報を誤って適用した可能性がある。

  このことから、ファインチューニングによって設計者の意図する出力形式や回答ルールを反映しやすくなるものの、質問の意味や回答の根拠を常に正しく判断できるとは限らないと考える。

## 宿題

- **取り組んだレベル**：基礎

- **変えた設定やデータ**：
  - `CONFIG` の `num_train_epochs` を20から10に変更した。
  - ベースモデル、学習データ、学習率、LoRAランク、乱数シード、生成設定、評価用の21問は変更していない。
  - 変更後、ランタイムを再起動してセクション0から再実行した。

- **結果（比較表や数字）**：

| 評価項目 | 元の設定（20エポック） | 変更後（10エポック） |
|---|---:|---:|
| 学習データ数 | 14件 | 14件 |
| エポック数 | 20 | 10 |
| 学習ステップ数 | 40 | 20 |

| 学習時間 | 229秒 | 116秒 |
| 学習前の形式遵守率 | 9.5% | 9.5% |
| 学習後の形式遵守率 | 100% | 100% |
| 学習前の内容正解率 | 0% | 0% |
| 学習後の内容正解率 | 90.5%（19/21問） | 85.7%（18/21問） |

  **数値の比較**

  - 学習時間は229秒から116秒となり、113秒（約49%）短縮した。
  - 最終記録Lossは20エポックで0.013719、10エポックで0.098481だった。
  - 学習後の形式遵守率は両条件とも100%だった。
  - 学習後の内容正解率は20エポックが90.5%、10エポックが85.7%で、4.8ポイント（1問分）の差があった。

  **FAQに根拠があるかどうかによる比較**

  `needs_review`の判定結果を、FAQに根拠がある質問とない質問に分けて比較した。

| 評価対象 | 20エポック | 10エポック |
|---|---:|---:|
| FAQに根拠がある15問 | 15/15問正解 | 14/15問正解 |
| FAQに根拠がない6問 | 4/6問正解 | 6/6問正解 |

  20エポックでは、FAQに根拠がある質問への判定がすべて正しかった一方、根拠がない2問に対して誤って断定した。

  10エポックでは、FAQに根拠がない6問すべてで`needs_review=true`と判定できた。ただし、そのうち2問は回答文に採点上必要な「確認」という語句がなく、内容評価では不正解となった。また、FAQに根拠がある1問に対して誤って確認を求めた。

  **結果の考察**

  エポック数を20から10に減らした結果、学習時間は約49%短縮された。一方、形式遵守率はどちらも100%であり、内容正解率の差も4.8ポイントにとどまった。

  また、全体の内容正解率は20エポックの方が高かったものの、FAQに根拠がない質問への確認要否の判定は10エポックの方が良かった。20エポックでは、学習したFAQの回答パターンを、意味が近い別の質問に誤って適用した可能性がある。

  ただし、今回の評価は21問、各設定1回のみであるため、エポック数の増加が誤回答の原因であるとは断定できない。

  LLMを実際のサービスに導入する際には、タスクの特性に応じて、回答の正確性、根拠のない質問への対応、学習コストなどの評価指標を設定し、適切な学習量を検討することが重要だと考える。

- **ファインチューニングが向く場面・向かない場面についての考察**：

  ファインチューニングは、設計者が意図した回答形式や振る舞いをモデルに反映させたい場合に適していると考える。今回の実験でも、指定されたJSON形式の遵守率が大きく改善した。特に、多様な質問表現に対して一定の出力形式や回答スタイルを維持したい場合に有用だと考えられる。

  一方、FAQに根拠がない質問に対して誤った回答をする場合もあり、回答内容の正確性まで保証されるわけではなかった。そのため、厳密な正確性が求められる場面では、ファインチューニングだけでなく、外部情報の参照や回答内容の検証などを組み合わせることが重要だと考える。
