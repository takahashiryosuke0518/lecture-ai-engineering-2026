- 取り組んだレベル：実装
- やったこと：[app/retrieval.py](../../app/retrieval.py) の `search()` で、従来のベクトル検索SQLと順位付けの後に、ヒットしたページと同じ資料の前後1ページを追加取得する処理を実装した。資料IDとページ番号で照合するため、資料の境界を越えず、存在しないページも取得しない。検索ヒット自体は維持し、ページIDの重複を除いて、追加ページを `context_pages` に前・後の順で格納する。既存の検索結果フィールドと `search_materials`・agent の呼び出し仕様は維持した。検索件数は `RAG_TOP_K=5` のままである。追加テストを含め `uv run pytest -q` は29件すべて成功した。
- 比較条件：モデルは `gemini-3.5-flash-lite`、検索対象は第1〜3回の本講義資料、検索上位件数は5件である。Q1・Q3は同じ質問で実行した。Q2は検索語生成の揺れを除くため、HEAD版と改良版で検索語を「第2回 演習 学習用の手本データ 講義固有の事実」に固定した制御実験である。
